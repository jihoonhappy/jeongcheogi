# 정보처리기사 필기 트레이너

빌드 도구도 서버도 없이 동작하는 학습 앱. GitHub Pages에 올리면 PC·태블릿·휴대폰 어디서나 같은 주소로 접속하고, **홈 화면에 설치해 비행기 모드에서도** 쓸 수 있습니다.

```
index.html              앱 본체
manifest.webmanifest    PWA 설치 정보
sw.js                   오프라인 캐시 서비스 워커
icon-192.png            앱 아이콘
icon-512.png
.nojekyll               GitHub Pages 처리 우회
data/
  bank.js               문제은행 로더
  subject1.js           1과목 소프트웨어 설계        119문항
  subject2.js           2과목 소프트웨어 개발        118문항
  subject3.js           3과목 데이터베이스 구축      136문항
  subject4.js           4과목 프로그래밍 언어 활용   116문항
  subject5.js           5과목 정보시스템 구축관리    122문항
_kmap.md                출제기준 코드(k) 체계
_writing_rules.md       신규 문항 작성 규칙
_rewrite_rules.md       기존 문항 재작성 규칙
보완계획서.md            문제은행 감사 결과 및 보완 계획
```

총 **611문항** · 빈도 A 194 / B 269 / C 148 · 토픽 115종 (전 토픽 3문항 이상)

전 문항에 **공식 출제기준 코드(`k`)** 가 부여되어 있어, 통계 화면에서 Q-Net 출제기준의
주요항목 단위로 진도와 정답률을 확인할 수 있습니다. 출제기준 57개 세부항목을 모두 커버합니다.

## 1. GitHub Pages에 올리기

```bash
git init
git add .
git commit -m "정보처리기사 필기 트레이너"
git branch -M main
git remote add origin https://github.com/<사용자명>/<저장소명>.git
git push -u origin main
```

저장소 **Settings → Pages → Source: Deploy from a branch → Branch: main / (root)** 저장.

1~2분 뒤 `https://<사용자명>.github.io/<저장소명>/` 로 접속됩니다.

> Pages는 무료 플랜에서 Public 저장소만 지원합니다. Private으로 두려면 로컬에서 `index.html`을 직접 열어도 되지만, 이 경우 오프라인 캐시(서비스 워커)는 동작하지 않습니다.

## 2. 휴대폰에 설치하기

| 기기 | 방법 |
|---|---|
| iPhone·iPad | Safari로 접속 → 공유 버튼 → **홈 화면에 추가** |
| Android | Chrome으로 접속 → 메뉴 → **앱 설치** |

설치 후에는 주소창 없는 전체 화면으로 실행되고, **네트워크가 없어도 그대로 열립니다.** 문제은행 전체가 기기에 캐시되기 때문입니다.

### 눈 감고 학습 — 듣기 · 말하기

눈이 피로하거나 자기 전에 화면을 보지 않고 학습하는 모드입니다. 브라우저 내장 음성 기능을 쓰므로 파일을 받거나 서버를 둘 필요가 없습니다.

| | 듣기만 🎧 | 듣고 말하기 🎙 |
|---|---|---|
| 흐름 | 문제 → 보기 → 생각할 시간(3~12초) → 정답 → 해설 | 문제 → 보기 → **마이크 켜짐** → 채점 → 해설 |
| 응답 | 없음 | "2번"처럼 번호를 말함 |
| 학습 기록 | **반영 안 함** | **반영함** (복습 단계·정답률·히트맵) |
| 쓰임 | 자기 전, 눈이 아플 때 | 실제로 풀고 싶을 때 |

시작한 뒤에도 화면에서 두 방식을 바로 바꿀 수 있습니다.

**말로 하는 조작** — `"2번"` 답하기 · `"모르겠어"` 모르겠음 처리(내일 다시 출제) · `"다음"` · `"다시"` · `"그만"`
숫자는 `1번 / 일 / 하나 / 첫번째` 같은 여러 표현을 모두 알아듣습니다. 두 번 못 알아들으면 모르겠음으로 넘어갑니다.

**손으로 하는 조작**

| 재생·정지 | 다음 | 이전 | 다시 |
|---|---|---|---|
| 가운데 큰 버튼 · **스페이스** | **→** | **←** | **R** |

**목소리 고르기** — 기기에 설치된 한국어 음성을 목록에서 고르면 바로 미리 들려줍니다. 이름에 `Google`이나 `Siri`가 들어간 음성이 대체로 자연스럽습니다. 목록이 빈약하면 기기에서 고품질 음성을 내려받아야 합니다(macOS·iOS: 설정 → 손쉬운 사용 → 말하기 → 시스템 음성 → 한국어).

**자연스러운 낭독을 위한 처리**

- 영문 약어 약 190개를 한글 발음으로 바꿔 읽습니다. `SQL` → 에스큐엘, `UML` → 유엠엘, `HIGHT` → 하이트
- 한글 뒤 괄호 속 영문은 빼고 읽습니다. `캡슐화(Encapsulation)` → "캡슐화"
- `→`는 "다음", `·`는 쉼표, `①②③④`는 "1번~4번"으로 읽습니다
- 긴 문장은 문장 단위로 쪼개 읽어 중간에 끊기지 않게 합니다

**한계**

- 코드·표·ASCII 트리가 든 문항은 귀로 들어서는 이해할 수 없어 자동 제외됩니다. 제외된 수를 화면에 표시합니다.
- 음성 인식은 Chrome·Safari에서만 됩니다(Firefox 미지원). 인식은 네트워크를 씁니다.
- **iPhone·iPad는 화면을 잠그면 재생이 멈춥니다.** iOS 제약이라 우회할 수 없습니다. 재생 중에는 Wake Lock으로 화면 꺼짐을 막지만, 잠금 버튼을 직접 누르면 멈춥니다.

### MP3로 만들어 듣기 — 화면을 잠가도 재생됩니다

앱의 듣기 모드는 브라우저 내장 음성을 쓰므로 품질에 한계가 있고, 화면을 잠그면 멈춥니다.
더 자연스러운 음성으로 듣거나 화면을 끄고 듣고 싶다면 MP3로 만들어 두면 됩니다.

**만드는 법 — 파인더에서 `tools/오디오만들기.command` 를 더블클릭**

터미널이 열리면서 필요한 것을 확인하고, 목소리 맛보기를 먼저 만들어 들려준 뒤, 1과목 전체를 만듭니다.
중간에 멈춰도 다시 실행하면 이어서 만듭니다.

터미널을 직접 쓰신다면:

```bash
pip3 install edge-tts                          # 한 번만
python3 tools/make_audio.py --list-voices      # 쓸 수 있는 목소리 보기
python3 tools/make_audio.py --sample           # 목소리별 맛보기
python3 tools/make_audio.py --subject 1        # 1과목 만들기
python3 tools/make_audio.py --all              # 5과목 전부
```

| 옵션 | 뜻 | 기본값 |
|---|---|---|
| `--voice` | 목소리 이름 | `ko-KR-SunHiNeural` |
| `--gap` | 생각할 시간(초) | `5` |
| `--group` | 한 파일에 담을 문항 수 | `10` |
| `--rate` | 말 빠르기 (예: `+10%`) | 기본 속도 |
| `--engine` | `edge`(신경망) 또는 `say`(맥 내장) | 자동 |

**음성 엔진**

| | edge-tts | macOS `say` |
|---|---|---|
| 품질 | 신경망 음성. 사람이 읽는 것에 가까움 | 시스템 음성. '고급' 설치 시 쓸 만함 |
| 인터넷 | 필요 | 불필요 |
| 비용·계정 | 무료, 키 불필요 | 불필요 |

**쓸 수 있는 한국어 목소리는 엔진에 따라 다릅니다.** 먼저 확인하세요.

```bash
python3 tools/make_audio.py --list-voices
```

없는 이름을 주면 0바이트 파일이 만들어집니다. 그래서 본 작업을 시작하기 전에
목소리 이름을 검사하고, 없으면 실제 목록을 보여 주며 멈춥니다.

| 엔진 | 한국어 목소리 | 준비물 | 비용 |
|---|---|---|---|
| `edge` (기본) | 목록이 짧습니다. `--list-voices` 로 확인 | `pip3 install edge-tts` | 무료·계정 불필요 |
| `azure` | JiMin·SeoHyeon·YuJin·SoonBok 등 여성 여럿 | Azure 계정 + 키 | 월 50만 자까지 무료 |
| `say` | 유나 등 macOS 설치 음성 | macOS | 무료·인터넷 불필요 |

5과목 전체 낭독이 약 17만 자이므로 **Azure 무료 한도(월 50만 자) 안에 전부 들어갑니다.**

```bash
export AZURE_SPEECH_KEY=발급받은키
python3 tools/make_audio.py --subject 2 --engine azure --voice ko-KR-JiMinNeural
```

**목소리 선택지를 넓히는 두 가지 방법**

무료 edge-tts 의 한국어 전용 음성은 몇 개 없습니다. 그래서 두 갈래로 늘립니다.

① **높낮이·빠르기 바꾸기** — `이름@높낮이@빠르기` 로 지정합니다.

| 지정 | 느낌 |
|---|---|
| `ko-KR-SunHiNeural` | 기본 |
| `ko-KR-SunHiNeural@-15Hz` | 낮고 차분하게 (자기 전) |
| `ko-KR-SunHiNeural@+15Hz` | 밝게 |
| `ko-KR-SunHiNeural@+22Hz@+6%` | **밝고 또렷하게, 살짝 빠르게** |
| `ko-KR-SunHiNeural@-8Hz@-8%` | 낮고 느리게 |

② **다국어(Multilingual) 음성 쓰기** — 한국어도 읽습니다. 완전히 다른 목소리를 얻는 방법입니다.

```bash
python3 tools/make_audio.py --sample --multi
```

서버 목록에서 이름에 `Multilingual` 이 든 여성 음성을 찾아 맛보기를 만듭니다.
`en-US-AvaMultilingualNeural`(밝고 또렷), `en-US-EmmaMultilingualNeural`(부드러움),
`fr-FR-VivienneMultilingualNeural`(또렷하고 경쾌) 같은 것들이 나옵니다.

> 다국어 음성은 한국어 억양이 살짝 다를 수 있습니다. 반드시 맛보기로 들어 보고 정하세요.
> 잘 맞으면 한국어 전용 음성보다 또렷하고 생기 있게 들리는 경우가 많습니다.

과목마다 다르게 주면 지금 무엇을 듣고 있는지 귀로 구분됩니다.

**끊어 읽기**

문항을 한 번에 길게 읽히면 음성 엔진이 끊어 읽는 위치를 제멋대로 잡아 부자연스러워집니다.
그래서 문제·보기 하나하나를 따로 합성하고 그 사이에 정확한 길이의 무음을 넣습니다.

| 조각 | 뒤 간격 |
|---|---|
| "삼십칠번 문제." | 0.45초 |
| 문제 지문 | 0.7초 |
| 보기 1~4 (각각) | 0.45초 |
| "정답을 생각해 보세요." | `--gap` (기본 5초) |
| "정답은 이번, …" | 0.6초 |
| "해설. …" | 1.4초 |

**숫자 읽기**

`1번`을 그대로 읽히면 음성 엔진이 **"한 번"(횟수)** 으로 읽습니다. 그래서 한자어 한글로 바꿔 넣습니다.

| 원문 | 읽히는 말 |
|---|---|
| `1번, 2번, 3번, 4번` | 일번, 이번, 삼번, 사번 |
| `37번 문제` | 삼십칠번 문제 |
| `계-위-개-고` | 계, 위, 개, 고 |
| `계획 수립 → 위험 분석` | 계획 수립, 그다음 위험 분석 |

**결과물**

`audio/1과목_소프트웨어설계/` 아래에 `1과목_01_001-010.mp3` 형태로 10문항씩 묶여 생깁니다.
1과목 기준 **12개 파일, 약 2시간, 42MB**입니다. 곡 정보(제목·앨범·트랙)가 붙어 음악 앱에서 순서대로 재생됩니다.

낭독 대본은 앱의 듣기 모드와 같은 규칙으로 만들어집니다 — 약어를 한글 발음으로 바꾸고, 괄호 속 영문을 빼고, `→`를 "다음"으로 읽습니다. 약어 사전은 `index.html`의 `ABBR` 하나만 고치면 앱과 MP3에 함께 반영됩니다.

**만든 파일은 저장소에 올라가지 않습니다**

`audio/` 는 `.gitignore` 대상입니다. 그래서 **만든 PC 에만 남고, git push 해도 다른 기기에는 가지 않습니다.**
한 번 지우면 되돌릴 수도 없습니다. 맛보기만 지울 때는 폴더를 통째로 지우지 말고 아래를 쓰세요.

```bash
python3 tools/make_audio.py --clean-samples   # 샘플만 삭제, 과목 폴더는 그대로
```

만들어 둔 과목이 있으면 실행할 때 알려 주고 건너뜁니다. 다른 목소리로 다시 만들려면 `--force`.

### 앱에서 바로 재생하기 — 자면서 듣기

만든 MP3 를 사이트에 올려 두면 **앱 안의 플레이어**로 재생할 수 있습니다.
브라우저 내장 음성과 달리 **화면을 잠가도 재생이 이어지고**, 잠금화면과 이어폰 버튼으로 조작됩니다.

| 기능 | 설명 |
|---|---|
| 수면 타이머 | 15·30·45·60분. 끝나기 30초 전부터 소리를 줄이며 멈춥니다 |
| 이어듣기 | 마지막 트랙과 위치를 기억합니다 |
| 잠금화면 조작 | 재생·정지·앞뒤 트랙·15초 뒤로·30초 앞으로 |
| 연속 재생 | 한 트랙이 끝나면 다음으로 넘어갑니다 |

**올리는 방법**

```bash
python3 tools/make_audio.py --manifest    # 트랙 목록(audio-manifest.json) 생성
```

그다음 `.gitignore` 에서 `audio/` 줄을 지우고 `audio/` 폴더와 `audio-manifest.json` 을 함께 push 하면
휴대폰에서 사이트에 접속해 바로 들을 수 있습니다.

저장소를 무겁게 하고 싶지 않다면 **GitHub Releases 에 올리고 앱에서 위치만 바꾸면** 됩니다.
플레이어 화면의 `파일 위치 바꾸기` 에 릴리스 주소를 넣으세요.
이 경우 저장소에는 `audio-manifest.json` 하나만 올리면 됩니다.

> 음성 파일은 서비스 워커가 오프라인 캐시에 담지 않습니다.
> 과목 전체가 200MB 가 넘어 기기 저장공간을 잡아먹기 때문입니다.

### 파일을 직접 옮기려면

| 방법 | 어떻게 | 언제 좋은가 |
|---|---|---|
| **클라우드 폴더로 복사** | `--copy-to ~/Library/Mobile\ Documents/com~apple~CloudDocs/정처기음성` | iPhone 파일 앱에서 바로 재생 |
| **음악 앱에 넣기** | `audio/` 의 mp3 를 음악 앱으로 끌어다 놓고 기기 동기화 | 오프라인 재생. 데이터를 안 씁니다 |
| **zip 으로 묶어 전송** | `--zip` → AirDrop | 다른 PC 로 한 번에 |

**둘은 대체재가 아니라 보완재입니다.** 평소·외출 중에는 앱 듣기 모드를,

## 6. 문제 추가하기

해당 과목 파일에 객체를 덧붙이면 앱이 자동 인식합니다.

```js
{
  id: 5201,             // 고유 번호 (과목별 대역: 1xxx~5xxx)
  s: 5,                 // 과목 1~5
  k: "5-4-1",           // 출제기준 코드 "과목-주요항목-세부항목" (_kmap.md 참조)
  t: "암호화",           // 토픽 — 약점 분석 단위
  f: "A",               // 빈도 A(최다) / B(자주) / C(가끔)
  q: "문제 지문",         // \n 으로 줄바꿈 가능
  c: ["보기1","보기2","보기3","보기4"],
  a: 2,                 // 정답 인덱스 (0부터)
  e: "해설"
}
```

**중요:** 문제은행을 수정한 뒤에는 `sw.js`의 `CACHE` 버전을 한 단계 올려야 설치된 기기에 새 문항이 반영됩니다. 캐시가 갱신되지 않으면 예전 문제만 계속 나옵니다.

```bash
git add . && git commit -m "문제 추가" && git push
```

기존 학습 기록은 문항 id 기준으로 유지됩니다.

## 8. 출제기준 코드(k)

각 문항에는 공식 출제기준(Q-Net)의 위치를 가리키는 `k` 필드가 있습니다.

```
k: "5-4-1"
    │ │ └── 세부항목: 시스템 보안 설계
    │ └──── 주요항목: 시스템 보안 구축
    └────── 과목: 정보시스템 구축관리
```

코드 전체 목록은 `_kmap.md`에 있고, 앱의 `KMAP` 상수와 동일합니다.
통계 화면의 **출제기준 영역별 진단**이 이 값을 집계해 주요항목 단위 진도와 정답률을 보여줍니다.
토픽은 학습 편의를 위해 앱이 정한 단위지만, 이 표는 **실제 시험 범위 그 자체**를 기준으로 합니다.

문항을 추가할 때는 `_kmap.md`에 있는 코드만 사용하세요. 표에 없는 값을 쓰면 진단표에서 누락됩니다.

## 9. 문항 작성 규칙

문제은행의 품질을 유지하기 위한 규칙이 `_writing_rules.md`(신규)와 `_rewrite_rules.md`(수정)에 정리되어 있습니다. 핵심만 옮기면,

- 오답 보기 4개를 **같은 계열·같은 층위의 실재하는 개념**으로 구성할 것.
  존재하지 않는 조어("정규 분할", "비용 뷰"), 존재하지 않는 구문(`WHERE 점수 == NULL`),
  범주가 다른 오답("개발자 연봉")은 지식 없이도 소거되므로 금지합니다.
- **지문에 정답을 노출하지 말 것.** "비동기로 주고받는" → AJAX, "견본품을 미리 만들어" → 프로토타입 같은 형태입니다.
- **해설에 다른 문항의 정답을 나열하지 말 것.** 앞 문항 해설을 읽으면 뒤 문항이 자동으로 풀립니다.
- 해설은 **60자 이상**, 오답 중 최소 하나가 왜 틀렸는지 설명할 것.
- 계산·코드·SQL 문항은 **실제로 실행하거나 계산해서** 정답을 확인할 것.
- 정답 인덱스를 0~3에 고르게 배분할 것.
